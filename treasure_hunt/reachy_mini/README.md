# Treasure Hunt — Reachy Mini Integration

This folder contains everything needed to deploy the Reachy Mini robot as an
optional narrator for Treasure Hunt. When the robot is not available, the game
runs exactly as before.

The Reachy Mini **Control app is not required**. This agent runs beside the
built-in `reachy-mini-daemon` using SSH.

**Moving the game host from Windows to Linux / Raspberry Pi OS?** See
[LINUX.md](LINUX.md). The `.py` files in *this* folder stay on the robot;
host-side edits are in `computer_app/config.py` only.

---

## What the robot does

- Speaks game events through an American female narrator voice.
- On each confirmed find, announces which hunter found which treasure
  (e.g. "Yes! Hunter two, has found treasure one!") using pre-rendered
  fragment WAVs composed at runtime — not a full hunter×treasure matrix.
- Emotes (head nods, antenna expressions) on key moments.
- Optionally gazes at the nearest face/movement (camera gaze, disabled by default).
- Orchestrates the **player identification** ceremony when enabled on the setup page.
- Never scores a find — every game result still comes from the micro:bits.

## Requirements

### On the game host (PC / Raspberry Pi B+)
- Python 3.8+ (same environment as the Treasure Hunt app)
- OpenSSH client — `ssh` and `scp` in PATH
  - Windows 10/11: built-in at `%SystemRoot%\System32\OpenSSH\`
  - Linux/macOS/Raspberry Pi OS: pre-installed

### On the robot (Reachy Mini Wireless CM4)
- `reachy-mini-daemon` running (starts automatically on power-on)
- `/venvs/apps_venv/bin/python` — the onboard venv (already present)

## 1 — Initial network setup

1. Power on the robot. It broadcasts its hostname as `reachy-mini.local`.
2. Copy the CLI config once and set your robot host IP (or `.local` name):

   ```
   cd treasure_hunt/reachy_mini
   copy reachy_cli.config.example.json reachy_cli.config.json
   ```

   On Linux/macOS use `cp` instead of `copy`. Edit `host` in
   `reachy_cli.config.json` (for example `pollen@192.168.1.65` or
   `pollen@reachy-mini.local`). This file is gitignored so each machine keeps
   its own LAN address.
3. On the game host, test that the robot is reachable:

   ```
   ping reachy-mini.local
   ```

4. If `.local` does not resolve on Windows, find the IP address from your
   router's DHCP table or via the Reachy Mini Control dashboard
   (`http://reachy-mini.local:8000/`) and use the IP directly — either edit
   `reachy_cli.config.json` or pass `--host` once:

   ```
   python reachy_cli.py check --host pollen@192.168.1.42
   ```

## 2 — SSH key setup (do once per game host)

The management tool never stores passwords. Set up key-based auth instead.

### Windows (PowerShell)
```powershell
# Generate a key if you don't have one
ssh-keygen -t ed25519 -C "treasure-hunt"

# Copy it to the robot (will prompt for the default password: root)
$pubkey = Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
ssh pollen@reachy-mini.local "mkdir -p ~/.ssh && echo '$pubkey' >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

### Linux / macOS / Raspberry Pi OS
```bash
ssh-keygen -t ed25519 -C "treasure-hunt"   # if no key yet
ssh-copy-id pollen@reachy-mini.local       # prompts for password: root
```

Verify passwordless access:
```
ssh pollen@reachy-mini.local echo OK
```

## 3 — Build voice files (do once)

Download the Piper voice model (two files):
```
https://huggingface.co/rhasspy/piper-voices/tree/main/en/en_US/amy/medium
```
Save both `.onnx` and `.onnx.json` to either:
- `quest_engine/tools/voices/` (auto-discovered), or
- any folder, then pass `--model <path>`

Download the Piper binary for your OS:
```
https://github.com/rhasspy/piper/releases
```

Render the WAVs:
```
cd treasure_hunt/reachy_mini
python build_voice.py --piper /path/to/piper --model /path/to/en_US-amy-medium.onnx
```

No Piper? Install `pyttsx3` for a robotic fallback:
```
pip install pyttsx3
python build_voice.py
```

## 5 — Configure (optional)

Edit `/home/pollen/treasure_hunt_reachy/config.json` on the robot:

```
ssh pollen@reachy-mini.local
nano /home/pollen/treasure_hunt_reachy/config.json
```

Key settings:

| Key | Default | Description |
|-----|---------|-------------|
| `bind_port` | 7000 | HTTP port (must match `REACHY_AGENT_PORT` in computer_app/config.py) |
| `token` | `""` | Shared secret; leave empty on a trusted LAN |
| `narrate` | `true` | Speak through robot speaker |
| `emote` | `true` | Head and antenna expressions |
| `wobble` | `true` | Audio-reactive head movement |
| `track` | `false` | Auto-start gaze at agent boot; `POST /init` from the game also starts tracking |

## 6 — Persistent setup (recommended)

If the robot always uses the same Wi‑Fi and IP (`192.168.1.65`), do this **once**.
After that you only power on the robot and run the Treasure Hunt app — no manual
`start` before each session.

### Already configured in this repo

| Setting | Value |
|---------|-------|
| Game host → agent | `REACHY_AGENT_HOST = '192.168.1.65'` in `computer_app/config.py` |
| CLI SSH target | `host` in local `reachy_cli.config.json` (from the example; not committed) |

Wi‑Fi credentials live on the robot itself (Reachy remembers your network after
the first join). Keep `192.168.1.65` stable with a **DHCP reservation** on your
router if the address is not already fixed.

### One-time install (from the game host)

1. SSH keys (§2) — only if not done yet.
2. Run the installer — deploys files and registers a systemd service on the robot:

   ```
   cd treasure_hunt/reachy_mini
   python reachy_cli.py install
   ```

   `install` runs `check`, `deploy`, then enables `treasure-hunt-reachy.service`
   so the agent starts automatically after the robot boots (once
   `reachy-mini-daemon` is up).

3. Confirm:

   ```
   python reachy_cli.py status
   ```

After install, **skip §6 manual start**. Re-run `install` only when agent code or
audio files change. Use `python reachy_cli.py deploy` for a quick file sync without
touching the service.

To remove auto-start: `python reachy_cli.py uninstall`

## 7 — Manual start / stop (without install)

If you did not run `install`, start the agent before each session:

```
python reachy_cli.py start     # start agent in background on robot
python reachy_cli.py status    # check process and /health
python reachy_cli.py logs      # tail agent log
python reachy_cli.py stop      # kill agent
```

## 8 — Enable in the game

1. In `computer_app/config.py` set **`USE_REACHY = True`** and point
   `REACHY_AGENT_HOST` at the robot.
2. Run the Treasure Hunt app: `python app.py`
   - With Reachy enabled, the host calls agent **`POST /init`** (full wake,
     voice/speaker path, and camera tracking).
3. Open `http://localhost:5000/setup`
4. Check **Use Reachy Mini** — the page verifies `/health` in real time.
5. Set number of hunters (up to 8) and treasures, then click **Start Game**
   (calls `/init` again before the identification ceremony).

If Reachy is enabled and all hunters are on micro:bit V2, an **Identification**
screen appears before gameplay. Each hunter holds the gold logo pad and enters
their assigned three-button code. If you cancel, the game starts without
identification.

## 9 — Player identification protocol

When Reachy is enabled, the game runs a short ceremony before the hunt:

1. **PC → bridge → radio:** `RG|S|<token>` — session starts
2. **Hunter holds logo pad** → micro:bit sends `RG|R|<nonce>|<token>` every ~300 ms
3. **Dashboard shows** missing count; Reachy announces hunters by name as they join
4. **Once all hunters are ready**, the PC assigns each a random 3-button code
5. **PC broadcasts** `RG|A|<nonce>|<token>|<code>` — hunter sees code, enters it
6. **Hunter sends** `RG|C|<nonce>|<token>|<entered>` after 3 presses
7. **PC validates** and broadcasts `RG|K|<nonce>|H<n>` on match
8. **Hunter sends** `RG|O|<nonce>|H<n>` and adopts the new ID

The eight unique codes are: `AAA AAB ABA ABB BAA BAB BBA BBB`.

Buttons A and B are used only for code entry during the ceremony; mute/claim
functions return after assignment.

**V2 requirement:** `pin_logo.is_touched()` requires micro:bit V2.
V1 devices can still play without the identification flow (leave Reachy unchecked).

## 11 — Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `SSH FAILED` | Key not installed / wrong hostname | Run step 2; try `--host pollen@<ip>` |
| `Health: unreachable` | Agent not started / firewall | Run `python reachy_cli.py install` once, or `start`; check port 7000 |
| Agent starts but no speech | WAVs not deployed | `python reachy_cli.py deploy` |
| Robot moves but no sound | `narrate: false` or WAV missing | Check `config.json`; run `build_voice.py` |
| Version mismatch error | SDK ≠ daemon version | Update robot via `http://reachy-mini.local:8000/settings` |
| Logo touch not detected | V1 micro:bit | V2 required for identification; use manual ID instead |
| `reachy_cli.py deploy` slow | Large audio folder | Normal — ~90 small WAV files; takes ~20s on Wi-Fi |

## Network / firewall note

The agent listens on port **7000** (TCP). The game host must be able to reach
this port on the robot's IP. On a home/school Wi-Fi network this is normally
fine. If `status` reports the agent running but `/health` is unreachable,
check the robot's firewall:

```
ssh pollen@reachy-mini.local "sudo ufw allow 7000/tcp"
```
